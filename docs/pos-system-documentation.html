1. Gambaran Sistem & Implementasi Lapangan

Prambanan & Ratu Boko Point of Sale (POS) adalah ekosistem aplikasi kasir dan manajemen multi-gudang (multi-warehouse) yang digunakan secara aktif oleh para kasir di seluruh titik tiket, suvenir, dan ritel di kawasan wisata Candi Prambanan dan Candi Ratu Boko.

Gambar 1: Antarmuka POS Checkout responsif dengan keyboard shortcuts dan navigasi cepat kasir.

Sistem dibangun untuk menghadapi tantangan transaksi berkecepatan tinggi dengan ribuan wisatawan per hari. Arsitekturnya menggabungkan web portal berbasis Laravel 13 + Inertia.js 3 + React 19 dengan aplikasi Android native (via Capacitor) yang terhubung langsung ke printer thermal Bluetooth (SPP) tanpa melalui perantara browser dialog.

2. Native Android Bluetooth Classic Printing (SPP)

Di loket kasir wisata, kecepatan mencetak struk adalah prioritas mutlak. Menggunakan dialog cetak bawaan browser Chrome menimbulkan jeda waktu (latency) 3-5 detik per transaksi.

Solusi yang diimplementasikan:

  • Capacitor Native Bridge: Menghubungkan antarmuka React dengan layer native Android Bluetooth Serial Port Profile (SPP).
  • Thermal ESC/POS Direct Stream: Data struk, logo toko, barcode/QR transaksi, dan perintah potong kertas (cutter) dikirim dalam bentuk raw byte stream langsung ke printer thermal (seperti BP-LITE80D).
  • Pencetakan Instan: Struk kasir, open bill, dan struk dapur tercetak secara otomatis (< 0.5 detik) begitu kasir menekan tombol bayar / shortcut enter, tanpa menampilkan pop-up browser.

3. Alur Data Multi-Gudang (Multi-Warehouse)

Cashier buka shift → pilih warehouse (Prambanan / Ratu Boko)
    ↓
POS memeriksa stok di product_warehouse (product_id + warehouse_id)
    ↓
Checkout → pengurangan stok atomik di product_warehouse
         → transaction.warehouse_id = shift.warehouse_id
    ↓
Purchase Order (PO) → Goods Receiving (GR) → Mutasi Stok Otomatis
Stock Transfer antar Destinasi: Source Gudang ──► Transit ──► Gudang Tujuan

Setiap pergerakan stok dicatat dalam StockMutationService untuk menjamin akurasi audit inventaris harian dan mencegah selisih barang antar titik penjualan.

4. Siklus Shift Kasir (Shift Lifecycle)

Setiap kasir wajib memiliki shift aktif untuk melakukan transaksi:

  • Buka Shift: Kasir memilih gudang lokasi, menginput modal awal (cash float), dan memulai sesi kasir.
  • Transaksi & Pembayaran: Mendukung pembayaran Tunai, QRIS Midtrans, Xendit, Transfer Bank, dan sistem piutang (open-bill).
  • Tutup Shift & Rekonsiliasi: Di akhir giliran kerja, sistem mencocokkan total uang tunai di laci fisik dengan kalkulasi sistem, mencatat selisih (over/short), dan mencetak ringkasan shift kasir.
