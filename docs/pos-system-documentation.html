1. Konteks & Masalah di Lapangan

Sistem Point of Sale (POS) ini saya kembangkan untuk menangani transaksi ritel, tiket, dan suvenir di loket kasir kawasan Candi Prambanan dan Keraton Ratu Boko. Sebelum sistem ini berjalan, kasir menghadapi kendala pencatatan stok multi-gudang yang lambat dan proses cetak struk via web browser yang memicu dialog pratinjau (print preview) dengan jeda 3 sampai 5 detik di tiap antrean pengunjung.

Gambar 1: Antarmuka POS Checkout kasir dengan integrasi keyboard shortcuts, pemilihan gudang aktif, dan klasifikasi metode bayar.

Aplikasi dibangun dengan stack Laravel 13 + Inertia.js 3 + React 19, dipaketkan ke tablet kasir Android menggunakan Capacitor agar dapat berbicara langsung dengan printer thermal via Bluetooth Serial (SPP).

2. Direct Printing Bluetooth Classic (SPP) ESC/POS

Di loket wisata saat musim liburan, antrean pengunjung sangat padat. Menggunakan fungsi cetak bawaan web (window.print()) tidak memungkinkan karena memicu pop-up Android/Chrome yang memperlambat kasir.

Pendekatan teknis yang saya terapkan:

  • Native Bluetooth Bridge: Memanfaatkan plugin Capacitor native untuk membuka socket Bluetooth Serial Port Profile (SPP) langsung ke printer thermal (seperti BP-LITE80D).
  • ESC/POS Raw Bytes: Format struk disusun langsung dalam byte array ESC/POS (karakter tebal, tata letak tabel, garis putus-putus, perataan teks, dan perintah potong kertas otomatis).
  • Cetak Instan (< 0.5 detik): Begitu kasir menekan tombol selesai bayar atau menekan tombol Enter pada keyboard fisik, byte data langsung dikirim ke printer tanpa dialog browser apa pun.

3. Klasifikasi Metode Pembayaran & Rekonsiliasi Kasir

Pada sistem POS ini, kasir tidak terhubung langsung ke API payment gateway eksternal (seperti Midtrans atau Xendit) secara otomatis, melainkan menggunakan toggle klasifikasi metode pembayaran di antarmuka kasir. Hal ini dirancang untuk menyederhanakan alur kerja kasir dan memudahkan pembukuan tim keuangan (finance).

Fungsi Toggle Pembayaran: Kasir memilih kanal pembayaran yang digunakan pengunjung saat transaksi berlangsung (Tunai, QRIS statis loket / EDC, Transfer Bank, atau Piutang / Open-Bill). Data ini langsung terklasifikasi pada database transaksi sehingga saat tutup shift, laporan kasir membedakan saldo fisik uang tunai di laci kas dari pemasukan non-tunai.
  • Tunai (Cash): Menghitung uang yang diterima, menghitung uang kembalian, dan menambahkan saldo pada laci kasir (cash drawer).
  • QRIS & Transfer Bank: Mencatat pembayaran non-tunai agar tidak tercampur dengan hitungan fisik uang laci saat serah terima shift.
  • Piutang (Open-Bill): Menyimpan nota gantung untuk pesanan rombongan atau rekanan sebelum penyelesaian pembayaran akhir.

4. Alur Multi-Gudang (Multi-Warehouse Inventory)

Kawasan wisata memiliki beberapa titik stok (Gudang Utama Prambanan, Loket Ratu Boko, dan titik souvenir). Sistem mengunci stok berdasarkan gudang yang dipilih saat kasir membuka shift: 

Kasir buka shift → pilih gudang (Prambanan / Ratu Boko)
    ↓
Sistem mengecek ketersediaan di product_warehouse (product_id + warehouse_id)
    ↓
Kasir transaksi → stok terpotong secara atomik di gudang tersebut
    ↓
Purchase Order (PO) → Goods Receiving (GR) → Mutasi stok otomatis bertambah
    ↓
Transfer Stok Antar Gudang: Gudang Asal ──► Status Transit ──► Gudang Tujuan

Pencatatan mutasi stok menggunakan service transaksi database untuk mencegah race condition saat kasir melayani transaksi bersamaan di lokasi berbeda.

5. Siklus Shift Kasir (Shift Lifecycle)

  • Buka Shift: Kasir memilih lokasi gudang, menginput modal uang tunai awal di laci (cash float), dan memulai jam operasional.
  • Pencatatan Transaksi: Setiap nota menyimpan shift_id kasir, waktu, rincian barang, dan klasifikasi metode bayar.
  • Tutup Shift & Rekonsiliasi: Kasir menghitung total uang fisik di laci dan memasukkannya ke sistem. Sistem membandingkannya dengan kalkulasi total penjualan tunai dan mencatat jika ada selisih (over/short), lalu mencetak struk rekapitulasi shift via Bluetooth thermal.

Komponen Teknologi Peran dalam Sistem
Backend Laravel 13 & PHP 8.3 RESTful routing, mutasi stok atomik, audit logs, dan autentikasi peran.
Frontend Kasir Inertia.js 3 + React 19 SPA responsif untuk interaksi kasir tanpa reload layar.
Styling Tailwind CSS Antarmuka keyboard-friendly dan tata letak ringkas untuk tablet loket.
Hardware Printing Capacitor Android + Bluetooth SPP Komunikasi socket byte stream langsung ke printer thermal 80mm (BP-LITE80D).
Klasifikasi Bayar Toggle Metode Pembayaran Kategorisasi Tunai, QRIS, Transfer, dan Open-Bill untuk rekonsiliasi keuangan.
Notifikasi Node.js whatsapp-web.js Layanan pengiriman otomatis nota transaksi & laporan harian via WhatsApp.
